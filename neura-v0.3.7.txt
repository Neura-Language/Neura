本版修 5 个 P0、6 个 P1、2 个 P2，新增 1 条 checker 规则、1 个 CI 三阶段流程。

1. 词法变更

1.1 §1.2 运算符表补 .. / ..=（B-3）

§1.2 运算符表追加：

```text
+ - * / % == != < <= > >= && || ! ~= = -> => . , : ; ( ) { } [ ] < > .. ..=
```

写死：.. 和 ..= 是独立 token，不拆分。lexer 扫描到 . 后立即 lookahead 下一字符：若下一字符是 .，再 lookahead 是否为 =：..= 合为三字符 token，.. 合为两字符 token；否则 . 是单字符 token。.. 不参与 postfix_expr 的 . 字段访问。

1.2 例外清单加「行首 = 抑制」（B-2）

§1.3 例外清单从 4 条改为 5 条：

```text
1. 行首 ( [ { , 抑制。
2. 行首二元运算符抑制：+ - * / % == != < <= > >= && || 。
   注释：< 和 > 的抑制在 lexer 层生效；parser 在 type 位置分派给 generic，
   在 expr 位置分派给比较运算符。
3. 行首 . 抑制。
4. 行首 = 抑制（新增）。
   注释：赋值语句跨行时，行首 = 抑制前一行插入 ;ᵥ。
   示例：self.last
           = Some(e)     // 合法：解析为 self.last = Some(e)
   副作用：let x = 1
             = 2          // 抑制后解析为 let x = 1 = 2，parser 报
                         // E-ASSIGN-LHS「= 左侧不能是字面量」，错误更准确。
5. 注释行不触发。
```

2. 语句与部署变更

2.1 规则 14 删除，并入规则 37（B-1）

§2.1 措辞改为：

原规则 14 的「do block 禁止 emit」语义已并入规则 37。规则 37 覆盖三种上下文：do block、fn block 禁止 emit，emit 仅 neuron handler 合法。§12 清单中删除规则 14，编号从 15 起顺延（见 §3 规则重排）。

§12 规则重排（v0.3.7）：原规则 14 删除，原规则 15–38 编号不变，新增规则 39。checker 清单从 38 条变为 38 条（删 14 加 39），编号有空洞但 CI 按错误码对拍不依赖编号。

2.2 规则 36 补 Range 显式声明（B-4）

§3 规则 36 追加：

Range 是 for 专用类型。用户不能显式声明 Range 类型变量、不能作为 fn 参数/返回值、不能构造除 a..b / a..=b 之外的 Range。let r: Range = 0..10 报 E-RANGE-OUTSIDE-FOR。Range 仅作为 for 的 expr 类型出现。

3. Checker 规则变更

3.1 规则 20 重写（C-2，span 定义）

```text
20. unit_lit 仅在 physics_value 位置合法；
    expr 位置见 [ "-" ] (int_lit | float_lit) ident 模式 →
    报 E-UNIT-OUTSIDE-PHYSICS，span 为 [ "-" ] (int|float) 的起始 token
    （有 - 时指向 -，无 - 时指向数值）。
    示例：let x = -55mV → span 指向 -（col 11）
          let x =  55mV → span 指向 55（col 11）
```

3.2 规则 35 补副作用清单（A-P0-5、B-6）

§3 规则 35 改为：

where 表达式中的 fn 调用必须是纯函数。副作用包括：emit、外部调用（非白名单）、修改 self、修改全局状态、learn（日志副作用）。局部 mut 变量赋值不算副作用（对外不可见）。is_hazardous / hash_of 视为纯，learn 视为非纯。fn 内 emit 已被规则 37 禁止，learn 在 fn 内合法但使其非纯。

3.3 规则 39 新增（B-6）

§12 追加：

```text
39. fn 内的局部 mut 变量赋值不算副作用，函数可视为纯函数（用于规则 35）。
    纯函数判定：无 emit、无外部调用（白名单外）、无 self 修改、无全局状态修改、
    无 learn 调用。is_hazardous / hash_of 视为纯；learn 视为非纯。
```

4. §17 重写（阶段 A：人工数 + 标注待验证）

4.1 §17 开头新增流程声明

§17 的 expected_error_span 分两阶段：

· 阶段 A（v0.3.7 当前）：人工数 + 标注 [待 parser 验证]。CI 跑 parser，输出实际 span，与 expected 比对，不一致 → warn（不阻断），提示「§17 N 的列号需更新」。
· 阶段 B（parser 实现后）：parser 输出实际 span → 人工确认正确 → 填入 §17 → CI 改为阻断模式。
· 阶段 C（稳定后）：§17 由 parser --dump-errors 自动生成，人工只审 message。

v0.3.7 的列号仍是人工数，parser 实现后必须由实际输出替换。 这是阶段 A 的诚实标注，不是最终数字。

4.5 §17 纪律（更新）

阶段 A（v0.3.7）：负例的 expected_error_span 人工数，标注 [待 parser 验证]。CI 跑 parser，输出实际 span，与 expected 比对，不一致 → warn（不阻断），生成 §17 列号待更新: N4 col 28→32 之类提示。人工确认 warn 内容，决定是否更新 §17。

阶段 B（parser 实现后）：parser 输出实际 span → 人工确认正确 → 更新 §17 → CI 改为阻断（不一致 → 阻断合并）。

阶段 C（稳定后）：parser --dump-errors 自动生成 §17 的 expected_error_span，人工只审 message。

v0.3.7 的列号是阶段 A 的人工数，不是最终数字。 任何「§17 列号已对齐」的声明必须附带 [parser 实际输出] 标注，否则视为阶段 A 未完成。

5. CI 流程（三阶段，新增）

§16 追加：

☐ 阶段 A CI（v0.3.7 当前）：跑 parser，输出实际 error span，与 §17 expected 比对。不一致 → warn，输出 diff，不阻断合并。人工确认后更新 §17。
☐ 阶段 B CI（parser 实现后）：同阶段 A，但不一致 → 阻断合并。§17 的 expected 必须与 parser 实际输出逐字段一致。
☐ 阶段 C CI（稳定后）：parser --dump-errors 生成 §17，CI 只校验 message 可读性（非空、不含 TODO、不含 [待 parser 验证]）。
☐ §17 自包含检查：脚本提取每条示例的未定义 ident，与前置定义块比对；有未定义且不在前置块 → 阻断合并。
☐ --dump-tokens diff：虚拟分号插入/不插入状态变化 → 阻断合并。
☐ .. / ..= token 校验：--dump-tokens 中 0..10 必须输出 int_lit .. int_lit，不得拆为 . .。

错误码注册表追加：
